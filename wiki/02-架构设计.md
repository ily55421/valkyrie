# 架构设计

## 整体架构

VALKYRIE DB 采用 Maven 多模块架构，遵循分层设计原则，将 UI、业务逻辑、数据访问、驱动抽象等分离到不同模块中。

```
┌─────────────────────────────────────────────────────────────┐
│                      launcher (启动层)                        │
│                    应用入口，main() 方法                       │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│                        app (UI层)                            │
│    JavaFX界面、事件总线、工作台、编辑器、对话框、自定义控件      │
└─────────┬───────────────────┬───────────────────┬───────────┘
          │                   │                   │
┌─────────▼───────┐  ┌────────▼────────┐  ┌──────▼──────────┐
│  core (核心层)   │  │  monacofx       │  │  blueprint      │
│  数据持久化/配置  │  │  Monaco编辑器   │  │  工作流封装     │
└─────────┬───────┘  └────────┬────────┘  └──────┬──────────┘
          │                   │                   │
┌─────────▼───────┐  ┌────────▼──────────────────▼──────────┐
│  drivers (驱动层)│  │            utils (工具层)             │
│  数据库驱动抽象   │◄─┤         通用工具类库                  │
└─────────┬───────┘  └──────────────────────────────────────┘
          │
┌─────────▼───────┐
│  各数据库驱动实现 │
│  MySQL/PG/SQLite │
│  DM/Redis        │
└─────────────────┘
```

## 模块结构

项目共包含 9 个 Maven 模块：

| 模块 | 职责 | 文件数 |
|------|------|--------|
| `launcher/` | 应用启动入口 | 1 Java |
| `app/` | JavaFX UI 层 | 99 Java |
| `core/` | 核心数据持久化与配置 | 11 Java |
| `drivers/` | 数据库驱动抽象层 | 71 Java |
| `utils/` | 通用工具库 | 73 Java |
| `monacofx/` | Monaco 编辑器 JavaFX 封装 | 1 Java + 120 JS |
| `richtextfx/` | 富文本组件（内嵌第三方） | 114 Java |
| `blueprint/` | 蓝图/工作流编辑器封装 | - |
| `test/` | 测试模块 | 1 Java |
| `workflow-editor/` | 前端工作流编辑器（React） | 7 TSX + 5 TS |

## 模块依赖关系

```
launcher → app → { core, monacofx, blueprint }
core → drivers → utils
monacofx → utils
blueprint → utils
richtextfx → (独立，被 app 通过 Maven 依赖引用)
```

依赖方向严格遵循从上到下的分层原则：
- 上层模块可以依赖下层模块
- 下层模块不能反向依赖上层模块
- 同层模块之间尽量减少依赖

## 核心设计模式

### 1. 驱动抽象模式 (Driver Abstraction)

`drivers` 模块定义了统一的 `Driver` 抽象基类和 `Dialect` 接口，不同数据库实现各自的驱动子类：

```java
public abstract class Driver implements SQLExecutor {
    public abstract DbType getType();
    public abstract Dialect createDialect();
    public abstract List<Table> getTables(Session session, String catalog, String schema);
    // ... 其他抽象方法
}
```

`DriverFactory` 根据连接配置创建对应的驱动实例：

```java
public class DriverFactory {
    public static Driver create(ConnectionConfig config, VkDataSource dataSource) {
        return config.getType().createDriver(dataSource);
    }
}
```

### 2. 数据源代理模式 (Connection Proxy)

通过 `ConnectionProxy` 和 `StatementProxy` 拦截 JDBC 操作，实现：
- SQL 执行 Hook（beforeExecute/afterExecute）
- SQL 日志记录
- 执行耗时统计
- 查询取消支持

### 3. 事件总线模式 (Event Bus)

`app` 模块实现了线程安全的事件总线，用于 UI 组件间解耦通信：

```java
public class EventBus {
    private final ConcurrentHashMap<Class<?>, CopyOnWriteArrayList<EventListener>> listeners;
    
    public void publish(Event event);
    public <T extends Event> void subscribe(Class<T> type, EventListener<T> listener);
}
```

### 4. 工厂模式 (Factory Pattern)

- `DriverFactory`: 创建驱动实例
- `VkDataSourceFactory`: 创建数据源
- `DbType`: 枚举工厂方法创建驱动

### 5. 可封存对象模式 (Sealable)

`drivers` 模块中的 `Column`、`Index` 等元数据对象继承 `Sealable`，提供完整性校验码防止篡改：

```java
public abstract class Sealable {
    private String integrityCode;
    public void finalIntegrityCode();  // 封存
    public boolean isTainted();        // 检测是否被篡改
}
```

## 关键架构决策

### 异步 SQL 执行
所有 SQL 操作在独立的单线程 `ExecutorService` 中执行，防止阻塞 JavaFX UI 线程。每个查询分配 jobId，支持取消正在执行的查询。

### HikariCP 连接池
使用 HikariCP 作为连接池实现，配置：
- 最大连接数：16
- 最小空闲连接：1
- 连接超时：30 秒

### JSON 文件持久化
连接配置、查询脚本等使用 JSON 文件存储在用户目录 `~/.valkyries/` 下，无需额外数据库。

### Monaco Editor 集成
通过 JavaFX WebView 嵌入 Monaco Editor，提供 VS Code 级别的代码编辑体验。

### 自定义 UI 控件
统一使用 `Vk*` 前缀的自定义控件（VkTabPane、VkTableView、VkComboBox 等），保证 UI 风格一致性。
