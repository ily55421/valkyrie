# 代码规范

## Git 提交规范

### 提交格式

```
模块名: 一句话描述改动
```

特殊类型（BUMP / BUILD / BUGFIX）可放在模块名前或独立使用。

### 示例

```
APP: 新增 脚本编辑器自动补全功能
DRIVER: 优化连接池初始化逻辑
APP/DRIVER: 调整连接创建流程
BUMP: 更新项目版本至 v1.0.0-arch.1
BUILD: 优化构建脚本
BUGFIX: 修复 脚本编辑器 Command+S 保存跳转问题
BUGFIX: 修复连接关闭后重新打开提示数据源已关闭
```

### 模块命名规则

1. 模块名必须使用 **大写英文**
2. 模块名使用 **单数形式**，不要使用复数
   - 例如模块目录为 `drivers`，提交时写 `DRIVER`
3. 如果一次提交涉及多个模块，**最多填写两个影响最大的模块**

| 目录 | 提交前缀 |
|------|----------|
| app/ | APP |
| core/ | CORE |
| drivers/ | DRIVER |
| utils/ | UTILS |
| monacofx/ | MONACOFX |
| richtextfx/ | RICHTEXTFX |
| launcher/ | LAUNCHER |
| blueprint/ | BLUEPRINT |
| workflow-editor/ | WORKFLOW |

### Bug 修复

Bug 修复必须使用 `BUGFIX` 前缀：

```
BUGFIX: 修复无主键表删除数据异常
BUGFIX: 修复连接关闭后重新打开提示数据源已关闭
```

### 版本号更新

版本号变更必须使用 `BUMP` 前缀：

```
BUMP: 更新项目版本至 v1.6.0
```

### 构建相关

构建脚本、CI/CD 配置、依赖更新等使用 `BUILD` 前缀：

```
BUILD: 优化 Maven 构建脚本
BUILD: 更新依赖版本
```

### 编写要求

1. 描述使用 **一句完整语义的短句**
2. 描述应 **直接说明改动内容或修复的问题**
3. 避免模糊描述

**不推荐：**
```
APP: 修改代码
APP: 一些优化
```

**推荐：**
```
APP: 新增查询结果分页功能
APP: 优化表结构加载性能
BUGFIX: 修复无主键表删除数据异常
```

## Java 编码规范

### 命名约定

| 类型 | 规范 | 示例 |
|------|------|------|
| 自定义UI控件 | 统一前缀 `Vk` | `VkTabPane`, `VkTableView`, `VkComboBox` |
| 包名 | 全小写，点分隔 | `valkyrie.app.widgets` |
| 类名 | 大驼峰 | `ConnectionProfile`, `QueryEditor` |
| 方法名 | 小驼峰 | `getTables()`, `executeQuery()` |
| 常量 | 全大写下划线 | `MAX_POOL_SIZE`, `DEFAULT_TIMEOUT` |
| 变量 | 小驼峰 | `connectionConfig`, `dataSource` |

### 核心原则

1. **核心逻辑剥离至 `core` 模块**，UI 模块只负责交互
2. **SQL 与数据库操作全程异步**，防止阻塞 UI 线程
3. **UI 样式统一管理**，避免硬编码样式
4. 优先使用 Lombok 注解减少样板代码（@Data, @Slf4j, @RequiredArgsConstructor）

### 异步执行规范

所有数据库操作必须在后台线程执行，使用 `ExecutorService` 或 `Task`：

```java
// 正确：异步执行
executor.submit(() -> {
    ResultSet rs = statement.executeQuery(sql);
    Platform.runLater(() -> updateUI(rs));
});

// 错误：在 UI 线程执行数据库操作
// ResultSet rs = statement.executeQuery(sql); // 会阻塞 UI
```

### 日志规范

使用 SLF4J + Logback，类上添加 `@Slf4j` 注解：

```java
@Slf4j
public class QueryEditor {
    public void execute(String sql) {
        log.info("Executing SQL: {}", sql);
        log.debug("Execution details: ...");
        log.error("Query failed", exception);
    }
}
```

日志级别使用：
- `error`: 系统错误、异常
- `warn`: 警告信息
- `info`: 重要业务信息
- `debug`: 调试信息
- `trace`: 详细跟踪信息

### 异常处理

1. 不要吞掉异常，至少记录日志
2. 使用自定义异常 `CoreException` 包装业务异常
3. UI 层向用户显示友好的错误提示

```java
try {
    driver.execute(sql);
} catch (SQLException e) {
    log.error("SQL execution failed", e);
    Platform.runLater(() -> VkDialogHelper.showError("执行失败", e.getMessage()));
}
```

## 前端编码规范（workflow-editor）

### TypeScript 规范

- 使用严格模式（strict: true）
- 优先使用接口定义类型
- 避免使用 `any` 类型

### React 规范

- 使用函数组件 + Hooks
- 组件名大驼峰
- 事件处理函数使用 `handle` 前缀

### CSS 规范

- 使用 CSS Modules 或 Tailwind CSS
- 类名使用 kebab-case

## 文档规范

- 公共 API 必须有 Javadoc 注释
- 复杂逻辑需要添加行内注释说明设计意图
- README 和 wiki 文档保持更新
